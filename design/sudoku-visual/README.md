# Hexadoku 16×16 — 三版视觉方案

为 gridpaw 的 16×16 数独（0–9 + A–F）做的三个**方向不同**的视觉原型。每个文件都是单文件、自包含、可直接双击打开，不需要构建，不依赖任何 JS 库。

- `A.html` — 紧凑网格 · Compact Solver Sheet
- `B.html` — 纸质棋谱 · Printed Puzzle Book
- `C.html` — 大触控格 · Big Grid Touch

三版共用同一份**真实可玩**的谜题数据：DLX 精确覆盖生成、校验唯一解，三档难度（Easy 112 givens / Medium 96 / Hard 93）。每版都实现了 16 符号键盘、四种格子状态、选中与同行同列同宫弱高亮、难度切换 / 新游戏、计时与 390px / 1280px 响应式。

## A · 紧凑网格（Compact Solver Sheet）

**设计决策**

- 把「一屏内看完整个盘面 + 所有工具」当第一目标。盘面 592px，右侧 274px 工具轨，1280×900 内完整落下，不滚动。
- 信息密度靠**工程图纸语言**撑住，而不是塞满文字：顶部是 `HEXADOKU / SHEET 016` 文档编号，盘面带 0–F 列标尺与 1–16 行标尺，当前行列标尺变琥珀色。
- 数字用系统等宽字体（SF Mono / Menlo / Consolas）。16 个符号宽度一致，盘面像排好的表格，快速扫读时不会跳动；这也是三版里唯一不用衬线数字的。
- 键盘 4×4、按键 64×42，按键角落显示「该符号还剩几个」；右侧把 Empty / Given / Your entry / Conflict 做成带计数的图例，并加一条 FILLED 进度条 —— 状态是「读数」，不是装饰。
- 冲突用砖红描边 + 淡红底，选中用琥珀实心；同行同列 `--peer`、同宫 `--boxpeer` 两级弱底色。颜色克制，避免桌面长时间解题时视觉疲劳。
- 文案口语化但克制：`Arrow keys walk the grid.` / `New sheet` / `ELAPSED`。

**交互**：点格选中，点键或直接按 0–9 / A–F 输入，Backspace 擦除，方向键走格；难度切换与 New sheet 立即重排；计时从 0 开始。

**代价**：移动端能用但不舒适（盘面 344px、格子 21px、键 40×38），它是明确的桌面优先方案。

## B · 纸质棋谱（Printed Puzzle Book）

**设计决策**

- 不做「像纸的 UI」，而是**直接做成一页纸**：桌面上放一张 660px 的纸，纸下压一张略旋转的衬纸，页眉 `GRIDPAW PUZZLE BOOK` / `HEXADOKU · NO. 16`，页脚 `PAGE 16` + `Printed in your browser`。
- 纸感由三层叠出来：暖奶油纸色、极淡的 SVG fractalNoise 纸纹（`mix-blend-mode: multiply`）、以及不全屏铺满的桌面底色。没有用任何图片素材。
- 全衬线：标题 Cormorant Garamond 52px，正文用 Iowan Old Style / Palatino 系统衬线，数字同为 Cormorant。细线 1px、4×4 分区 2px，像印刷制版而不是屏幕描边。
- 选中态是**手绘椭圆圈**（不规则 border-radius + 旋转），不是实心块；用户填入的数字用斜体 + 稍小字号，模拟铅笔字与印刷给定的区别。冲突是斜体砖红 + 下划线，像编辑用红笔圈出来。
- 键盘改成「The pencil tray」：8×2 两排，像文具盒里的印章；`Rub out a mark` 是带点线的文字链接。文案全部围绕纸和铅笔：`A sharp pencil is recommended.` / `Pencil marks agree so far.`
- 计时放在页脚左侧，和页码、状态并排，保持「书页」而不是「App 底栏」。

**交互**：点格 → 点托盘符号；键盘同样支持；冲突时页脚状态变砖红。

**代价**：盘面 408px、格子 25.5px，是三者中最小的；换取的是最强的品牌编辑感和「可以打印出来」的心智。手机上纸张占满宽度，格子 21px，仍可读但更适合阅读而非长时间手指操作。

## C · 大触控格（Big Grid Touch）

**设计决策**

- 移动优先。盘面不是一张网格，而是 **16 个独立的 4×4 圆角面板** 拼成，面板之间有 10px 的暖棕底色沟槽 —— 4×4 宫界不靠线，靠「块与块的缝」，手指按下去不会误判边界。
- 格子 34px、圆角 6px；选中格琥珀实心 + `scale(1.06)` + 投影，是全页最强的视觉锚点；同行同列 / 同宫用两级杏色底。
- 键盘是全页主角：4×4、66×58、圆角 14px，带 `0 3px 0` 的实体键边和按下位移，像一块真的按键托盘。每个键角标剩余数量。
- 额外做 **长按锁笔刷**：按住某键 420ms，键变琥珀并锁定；之后点任意格连续填同一符号（连击），再点任一键释放。这是三版里唯一为「一次填很多格」设计的交互，也是触控方向真正有用的差异点，而不是把按钮放大。
- 右侧 dock 有「当前格放大镜」：54px 的选中值 tile + `Row 2 · Col 7`，解决 16×16 在手机上格子太小、看不清当前值的问题。下方是进度条、三条极短规则、四状态图例。
- 所有圆角、阴影、按压反馈都指向「可以摸」；但配色仍是暖琥珀 + 奶油，没有任何冷色或玻璃拟态。

**交互**：点格 → 点大键；长按锁笔刷 → 连点格子涂；Erase / Restart；键盘同样可用。

**代价**：手机上整页约 1150px 高，需要滚动才能在盘面和大键盘之间移动（这是 16×16 + 大触控键的物理代价）；桌面端盘面 620px，右侧 dock 留白较多，但整体仍平衡。

## 技术说明

- **谜题生成**：`gen_puzzles.py`，DLX（Dancing Links）精确覆盖，先造完整终盘，再按目标 givens 挖洞并用 DLX 校验唯一解。固定种子 11 / 22 / 33 保证三档可复现。Easy 112、Medium 96、Hard 93 givens。
- **数据编码**：内部 1-based 计算，输出统一 0-based；页面用 `symbols = "0123456789ABCDEF"` 按 0–15 索引。每版加载时对谜题做随机旋转 / 镜像 / 符号置换（8 种几何变换均已验证为双射），所以三版即使同一难度也不会看到同一张盘面。
- **构建**：`build.py` 把 `puzzles.json` 注入 `*.template.html` 的 `__PUZZLE_DATA__` 占位符，生成 `A.html` / `B.html` / `C.html`。改模板后重跑 `python3 build.py A|B|C`。
- **字体**：Google Fonts（Cormorant Garamond / Nunito），带系统衬线、系统等宽回退；断网时仍可用，但气质会损失。
- **状态**：每版都实现 `.given` / `.user` / `.conflict` / `.sel` / `.peer` / `.boxpeer`，冲突检测按 16 行、16 列、16 宫全量标记重复值，不只标第一对。

## 没做什么

- 没有笔记 / 候选数模式、撤销、提示、自动检查、存档、音效、深色模式。这一轮只回答「16×16 数独长什么样」，不扩功能面。
- 没有接 gridpaw 的 Astro 布局、路由、SEO 或付费逻辑；三份都是独立 HTML 稿。
- 没有为 8 种旋转 / 镜像做 UI 开关；变换在加载时静默发生。
- 没有做打印样式表（`@media print`）；B 只是「打印心智」，不是真的可打印版面。

## 建议

如果只能选一版：**B** 最像 gridpaw 的品牌资产 —— 它把奶油纸、琥珀、Cormorant 衬线这三件事讲成了「一本数独册」，而不是「一个数独网页」，也最不容易被看成 AI 模板。**C** 是移动端最实用的一版，长按笔刷是真实增益；**A** 适合作为桌面端的「专业模式」，但它的等宽字体语言与品牌主线距离最远。

如果要上线一款产品，合理的组合是：**B 的视觉语言 + C 的触控交互**（移动端换大键与笔刷），A 只保留「标尺 / 状态计数 / 单屏密度」这几个信息设计决策。
