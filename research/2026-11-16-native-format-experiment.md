# Adsterra Native（无 iframe）格式对账实验 — 2026-11-16 起

> 起因：法老转述「Adsterra 去掉 iframe 收益更高」。核对结论：Banner 单元后台**没有**非 iframe 代码选项（法老已确认），
> 所以「去掉 iframe」在本站唯一可执行的形态 = **Native Banner**（unit 31317669，创意以 `<a><img>` 内联进页面 DOM）。
> 目标：2-3 天内拿到「Native CPM vs iframe Banner CPM」的同窗口对照，而不是拍脑袋。

## 一、实验设计（为什么这样切）

| 项 | 内容 |
|---|---|
| 测试组 | **8 个主力流量页**（GA4 近 7 天 PV 前列且带正文位：answers 450 / the-loop-past-answers 362 / level-33 360 / level-45 344 / level-42 321 / level-36 300 / level-17 278 / level-16 268，合计 2,683 PV/7d ≈ 383 PV/天）→ 正文位走 Native（`src/data/native-test-pages.ts`） |
| 对照组 | 其余 154 个带正文位的页面保持 300×250 iframe |
| 分组方法 | 2026-11-16 第二轮按法老指令收窄：**不做全量内页覆盖，只挑主要流量页**。旧的 66 页铺开方案已撤（那 66 页全回 iframe——铺太散信噪比差，且 native 的投诉风险面要尽量小） |
| 分账口径 | Adsterra 按 **placement** 分账：Native unit 31317669 的曝光全部来自这 8 页；banner unit 31836413 来自其余页 → 两个单元天然不重叠，**无需时间前后对比** |
| 观测窗口 | 2026-11-16 部署起，3 天 |
| 时区 | 一律 `timezone=GMT+08:00`（后台默认 GMT+0 会把同一天劈成两个桶） |

### ⚠ 11-16 排查出的关键事实：Native 单元当时是 Inactive

后台 `websites → 展开 gridpaw.com` 看到 **NativeBanner_1 (31317669) = Inactive**，Actions 里是 `RESUBMIT` 而不是 `GET CODE`。
这就是 11-16 全天 native 0 曝光的真因——**不是「native 不填充」，是单元根本没启用**。点 RESUBMIT 后约 3-5 分钟转 Active。
**教训：任何一个 unit 长期 0 曝光，第一步查单元状态，别先怀疑流量/格式/反作弊。**

## 三、预期与判据

- 测试组 ≈ 684 PV/天 → Native 约 600-700 imp/天，3 天约 1,800-2,100 imp。
- 判据不是「绝对收入涨了没有」（绝对额只有几毛），而是 **unit CPM 比值**：
  - Native CPM ≥ 2× banner CPM → 方向成立，值得讨论怎么开（受限于 10-15/10-29 两次投诉的形态记忆）
  - Native CPM ≈ banner CPM（<1.3×）→ 这条建议在本站不成立，直接结案、清空清单
- 统计噪声：日 CPM 最近 10 天在 $0.14–$0.30 之间摆动（CV≈30%），所以 4.5× 这种量级能读出来，20-30% 的差异读不出来——不要用小差异下结论。

## 四、风险与铁律（没变）

- Native 卡片是 **10-15 Reddit「ads immediately redirect」+ 10-29 第二次跳转投诉的直接形态来源**。这次只放 66 页、限 3 天，blast radius 受控。
- **任何一起跳转投诉 = 清空 `NATIVE_TEST_PATHS` 数组当天回滚**，不辩护。
- 上传的 changelog 2026-11-07 条目有一句「an ad is a fixed rectangle with an Advertisement label above it」——
  Native 卡片严格说不是「fixed rectangle」。本次实验未改该文案（3 天内部对照，非永久形态）；若决定长期开 Native，**这句必须先改再上**。
- 回滚：`src/data/native-test-pages.ts` 清空数组 → InContentAd 全站回 iframe。

## 四之二、广告覆盖度审计（2026-11-16，法老问「US CPM 0.3 是不是覆盖不够」）

**页面层**：490 页 → 372 页有广告码；118 页零广告全是故意的（akari 80 棋盘/play surface、meowdoku 11、
法务 4、/ad-free/、/unlock-all/、/offline/、/admin/、solver 首页等）。162 页有正文位（154 banner + 8 native）。

**视口层**（stub 实测 5 类页面 × 10 个宽度）：
| 视口 | 有正文位的页 | 普通页 | 游戏/play surface |
|---|---|---|---|
| ≥1350 | 左 160×600 + 右 160×300 + 300×250 | 左右侧栏 | 0 |
| 768–1349 | 728×90 sticky + 300×250 | sticky | 0 |
| <768 | 320×50 顶 + 300×250 + 底部 300×250（新） | 顶 + 底部（新） | 0 |

**流量层（GA4 7 天）**：12,156 PV —— mobile **83.6%**（10,168）、desktop 14.0%（1,705）、tablet 2.3%（283）。
手机 PV 里 **93%** 落在有正文位的页上（所以「手机只有一个小条」不成立）。

**实收 vs 请求**：代码层每周请求上限 ≈ 24,600（手机 19,633 + 桌面 4,544 + 平板 445），
后台实收 13,672 imp/周 → **填充率 56%**。分单元看：320×50 = 57%、300×250 ≈ 62%、160×600 = 20-40%（左右共用同 key 时）。

**CPM 结构（11-10~16）**：320×50 5,770 imp @ **$0.093**（42% 曝光）｜300×250 6,706 @ $0.390｜
160×600 687 @ $0.544｜728×90 509 @ $0.114 → 加权 $0.262。
US 单国：11-02~16 共 3,796 imp @ **$0.459**；单日 11-16 仅 54 imp @ $0.214（样本噪声，别当趋势）。

**结论：覆盖度不是 CPM 低的主因，库存结构是。** 42% 曝光是最贱的 320×50，而它承载的正是 83.6% 的手机流量；
即使把覆盖做到 100%，这套 banner 的天花板也只有 $0.4-0.55（160×600 是全站最高的）。要 $1 级别得换库存品类（native/popunder）或换网。
