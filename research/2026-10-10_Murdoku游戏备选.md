## 一、Murdoku 是什么

**数独 × 谋杀案推理**的混合品类。在一个带「房间」分区的网格里，把嫌疑人放进案发现场：每行每列一人（数独式位置约束）+ 每个房间恰一人（区域约束），线索是第一人称口供：

- 「我在冷冻区」→ 直接定房间
- 「我和小美相邻」→ 邻接约束，候选缩到相邻房间
- 「我在小甲南边」→ 方位约束（最南端脚下是墙，逻辑自动排除）
- 「我不靠墙」→ 边缘排除

文章的教学法值得抄：**先分房间再定格子**（分宿舍类比）——很多人卡死是因为一上来就抠坐标。这正好对应我们 hint 系统的分层提示设计（房间级 hint → 格位级 hint）。

## 三、与 gridpaw 的引擎复用评估

| 维度 | 评估 |
|---|---|
| 规则内核 | 行列唯一 + 房间唯一 = 我们已有的 **区域约束**（Nurikabe 的海岛、Heyawake 的房间同构），引擎复用度高 |
| 线索类型 | 口供线索是一阶逻辑（房间归属/邻接/方位/边缘），传播求解器可直接复用 nonogram 的 lineSolve 传播 + 回溯唯一性验证 |
| 生成器难点 | **线索集生成**：要保证唯一解且线索不冗余——先摆答案，再按信息量贪心选线索，回溯验证唯一。比 Nurikabe 生成器多一层，但可迭代 |
| 叙事层 | 每关一个微型案件（受害者/嫌疑人/场景），**天然是内容页素材**：每案一个故事页 = pSEO 页面，这是比现有六游戏更强的内容杠杆 |
| 猫主题化 | 嫌疑人 = 猫嫌疑人（橘猫/黑白猫/三花…），案发现场 = 各式房间。契合视觉 DNA，且叙事化视觉是差异化重点（用户视觉多样性偏好） |
| Hint | 分层：先亮「哪个房间定了」，再亮具体格——与谜题 hint「直接给答案数字」的偏好一致 |

## 四、风险与前置验证

1. **商标**：Murdoku 是书系品牌（Manuel Garand）。**不能用 Murdoku 名字**，用自己的名（如 Paw-doku / Whodoku / 猫侦探类）。SERP 主战场应选品类词 `murder mystery logic puzzle` / `murder sudoku`，不是品牌词（品牌词 KD 陷阱见 skill seo-keyword-selection）。
2. **搜索量未实测**：立项前必须 web.cafe 查 `murder sudoku` / `murder mystery logic puzzle` / `logic grid puzzle` 的量与 KD——`logic grid puzzle`（Zebra puzzle 品类）可能比 Murdoku 品牌词体量大得多。
3. **对照 09-16 结论**：当时结论是「现有资产曝光没起来之前不加新游戏」，Murdoku 同样受此约束；但它的**叙事内容页**是新变量——内容页不依赖游戏排名起量，可先行。
4. **合规**：谋杀题材对 AdSense 无障碍（侦探小说是常规品类），但避免血腥视觉，走「猫侦探」卡通调性。

## 五、若立项的建议排期
